依据：[2026-09-03 方案](../design/2026-09-03-multimodal-monitor-events-prompt.md) F4。
四个任务，一任务一提交。TDD。

## Task 1 SSE 客户端 + 事件查询端点

1. `panel-client.ts`：
   - `PanelEvent { id, ts, kind, message }` 投影
   - `getEvents(limit?, kind?)`：`GET /api/v1/events?limit=&kind=`（limit 默认 20 上限
     100；响应 `{events: [...]}`）
   - `streamEvents({ signal, onEvent }): () => void`：`fetch` GET
     `/api/v1/events/stream`（带 Authorization；**不走 request()**——那是单请求超时
     语义，SSE 是常驻连接）→ ReadableStream 逐行解析 SSE 帧（`data:` 行 JSON），
     snapshot 帧 `{type:'snapshot', events}` 与增量帧 `{type:'event', ...}` 都回调；
     返回停止函数（abort + reader 取消）。解析器抽纯函数（喂字符串行）便于单测
2. 单测：帧解析（snapshot/event/心跳注释行/跨 chunk 分帧）、auth 头、停止函数语义

## Task 2 status-watch（SSE 驱动 + 兜底轮询 + fleetCache + 事件环）

1. 新模块 `status-watch.ts` 吸收并**替代** `directory-refresh.ts`（删旧文件、迁测试）：
   - SSE 常连 + 指数退避重连（2s/5s/15s 封顶）；`model.*` 前缀事件 → 立即
     runtimeStatus diff → 变化则 `ctx.emit("llm/adapters-updated")`（复用现有语义）
   - 事件入环：最近 8 条内存 ring（`createEventRing`），供 gateway snapshot 下发
   - fleetCache：`{ running, models, fetchedAt }`，每次状态探测后写入（M5 的数据源）
   - 降级：SSE 连续失败 3 次 → 回退旧定时轮询（statusRefreshMs）；恢复后停轮询
   - `statusRefreshMs: 0` → 完全不启动（SSE 也不连——「不打扰面板」语义）
2. `index.ts`：`startDirectoryRefresh` → `startStatusWatch`；事件环实例在 index
   创建，喂 gatewayOptions（`events: () => ring.snapshot()`）
3. E2E：fake-panel-server 加 `GET /api/v1/events/stream` 假 SSE 端点 + 用例

## Task 3 卡片事件流 + Toast

1. `rpc-contract.ts`：`CardEvent` 类型 + `CardSnapshot.events: CardEvent[]` + codec
2. `panel-gateway.ts`：buildSnapshot 并入 `options.events?.() ?? []`
3. `client/state.ts`：新事件检测纯函数（上次快照 events ids ∖ 新 ids → 通知队列，
   只取 model.*/download.* 前缀）
4. `client/Card.tsx`：底部「最近事件」列表（model.exit 红 / download.complete 绿）；
   轮询发现新事件 → Toast（primatives 的 Toast，3s 自灭）
5. `client/locale.ts`：文案。单测：diff 函数、渲染分组
