# dsh 0.1.7 → 0.2.0 插件对接面差异调研（2026-09-30）

> 结论先行：**0.2.0-rc.2 对本插件的全部对接面都是加法变更，插件源码零改动即可兼容**。唯一的
> 硬阻断是插件管理器按 peerDependencies 范围做兼容门禁，旧范围 `<0.1.8-0` 在 0.2.0 宿主上会被
> 拒装；把三个 `@deepseek-ai/dsh-*` peer 的上限扩到 `<0.2.1-0` 即解决。
>
> 方法：npm 拉 `0.2.0-rc.2` 全部相关框架包，与本仓库 devDependencies（0.1.7-rc.1）逐包 diff
> `lib/`（类型 + 运行时），并重点核对派发路径对 adapter 的调用面（0.0.1→0.1.1 曾栽在运行时
> 无条件 `prepareCall` 上）。对照 GitHub release notes（v0.2.0-rc.1 汇总自 v0.1.7-rc.2）。

## 派发路径的行为变化（宿主侧，插件无需感知）

0.2.0 的 `dsh-llm` 在 adapter 派发前新增 `projectToolUpdates()` 投影：

- adapter 的 `resolveModel` 未声明 `toolUpdate`（本插件的情况）时，宿主先把 `role: "developer"`
  消息从 `options.messages` 里剥掉，再剥掉工具 schema 的 `deferLoading` 标记，然后才调
  `adapter.stream()`。插件收到的消息比 0.1.7 更干净，不需要新增处理。
- `listModels` 的文档语义收紧：「目录驱动的入口（如 GUI）可能要求模型在目录里；adapter 必须上报
  可用模型，基类空目录在 GUI 里没有可选项」。插件本来就实现 `listModels`，不受影响。

## 插件管理器的兼容门禁（本轮唯一要改的东西）

`@deepseek-ai/dsh-app-boot@0.2.0-rc.2` 的 `evaluatePluginCompatibility`：

```js
semver.satisfies(runtimeVersion, requirement, { includePrerelease: true })
```

- 只检查 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*` 开头的 peer；
- `includePrerelease: true` 意味着 `0.2.0-rc.2` 能满足 `>=0.1.5-rc.3 <0.2.1-0`（严格 npm semver
  语义下跨版本元组的预发布本来不进范围，这里显式放开）；
- `workspace:^/~/*` 视为「当前运行时版本」；
- 不兼容时安装直接失败（`incompatible-version`），支持按 `插件名@版本 → 运行时版本` 白名单豁免。

注意区分：pnpm 自己在 profile 里仍会报 `missing peer @deepseek-ai/dsh-llm ...` 警告——那是因为
profile 的依赖图里没有这些框架包（运行时由宿主 hoisted 树提供），0.1.7 时代同样存在，良性，
与 dsh 的兼容判定无关。

## 版本与发布事实

- npm：`@deepseek-ai/dsh` dist-tags `latest`/`next` = `0.2.0-rc.2`（2026-09-29 发布）；全部
  `dsh-*` 框架包同步发了 `0.2.0-rc.1`/`0.2.0-rc.2`。
- 桌面版 0.2.0-rc.2（`/Applications/DeepSeek Harness.app`）自带 Node/pnpm 运行时，DSH_HOME 在
  `~/Library/Application Support/dsh-desktop/harness`，与 CLI 的 `~/.dsh` 互不相干；其 profile
  框架包版本由 App 自己管理。
- CLI 0.2.0（npm 全局）安装时会把共享 profile 工作区（`~/.dsh/profiles/node_modules`）的框架
  刷到同代，无需手动重装 profile。

## 采纳的改动

1. peer 三项 `>=0.1.5-rc.3 <0.1.8-0` → `>=0.1.5-rc.3 <0.2.1-0`（上限收到 0.2.0 一代，0.2.1
   出来后按惯例先跑矩阵再扩）。
2. devDependencies 的 `@deepseek-ai/dsh-*` 全部 0.1.7-rc.1 → 0.2.0-rc.2（类型检查基线换到
   最新一代）；`typecheck` 零错误，佐证「全是加法」。
3. `scripts/test-compat.mjs` 从单代（0.1.5）扩成逐代矩阵：0.1.7-rc.1（cordis 4.0.4 /
   schemastery 3.18.4）+ 0.1.5-rc.3（4.0.2 / 3.18.2）。
