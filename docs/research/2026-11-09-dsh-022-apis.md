# dsh 0.2.1 → 0.2.2 插件对接面差异调研（2026-11-09）

> 结论先行：**0.2.2-rc.1 对本插件的全部对接面是加法变更或内部重构，插件源码零改动
> 即可兼容**。唯一的硬阻断仍是插件管理器按 peerDependencies 范围做的兼容门禁，旧范围
> `<0.2.2-0` 在 0.2.2 宿主上会被拒装；把三个 `@deepseek-ai/dsh-*` peer 的上限扩到
> `<0.2.3-0` 即解决。
>
> 方法：npm 拉 `0.2.2-rc.1`（dist-tags `latest`/`next`，2026-11-04 发布）全部 14 个
> 对接面包 + 基座 cordis/schemastery，与 `0.2.1-rc.5`（上一代 latest）逐包 diff `lib/`
> （类型 + 运行时）。0.2.1-rc.1→rc.5 的差异已于 2026-11-03 核对为零（ui-primitives
> 纯加法），故基线取 rc.5。宿主门禁同款 semver（`includePrerelease: true`）实测
> `0.2.2-rc.1`/`0.2.2-alpha.3`/`0.2.2` 满足 `<0.2.3-0`，`0.2.3-alpha.1`/`0.2.3-rc.1`
> 正确被拒。

## 逐包 diff 结果

| 包 | 结论 |
|---|---|
| `dsh-llm` | **`LlmAdapter` 抽象类类型声明逐字节未变**；`LlmError`/`attributionHeaders`/`ReasoningEffortId`/`ToolCallId`/`EMPTY_RESPONSE_CODE` 全部未动。`LlmModelInfo` 新增可选 `badge`（宿主 `listModels()` 规范化时透传，adapter 不返回也合法）；`GenerateOptions` 泛型化为 `GenerateOptions<Purpose extends string = LlmRequestPurpose>`，`purpose` 从字面量联合改为由产包方模块增强声明的 `LlmRequestPurposeMap`（本包内为空 map），**插件不读 `purpose`，不受影响**；新增 `llm/models-updated` 事件、`ShareViewerPrincipal`、`action-cards` 消息源，均为加法 |
| `dsh-tools` | 新增 pipeline/batch/executor/ptc/testing 模块（宿主侧）；`ToolDefinition` 移入 `contracts.ts` 但仅注释措辞变化（registry→executor），字段零变化；**`defineTool` 签名逐字节一致**；顶层 `export * from './contracts.ts'` 等保持 `defineTool`/`ToolDefinition` 包根导出 |
| `dsh-typert-protocol` | 变化全部集中在 resources 注册表：`TypertResourceDeclaration` 从 `{field}` 扩为 `{field} \| {resolve}` 二选一（宿主内部访问控制用，插件不注册 resources）；`TypertRemoteService` 基类、`InvocationDescriptor`、`TypertCodec`、`TypertRegistryContract` 未变 |
| `dsh-typert-registry` | resources 实现配套扩展；`register()` 契约未变 |
| `dsh-api-gateway` | 新增 `getPendingRemoteEvents()`（加法）；strict codec 消费入口 `codec.create().parse()` 不在 diff 中 |
| `dsh-attachment` | `HostPromptContent` image 分支新增 `encodedBytes` 字段；**`ImageAttachmentRef` 未变** |
| `dsh-client-locale` | 新增 6 个语言包（de/es/fr/ja/pt/ru）目录；`register()` 的 dicts 参数类型扩为 `Record<BuiltInLocaleId, …> & Record<LocaleId, …>`，`LocaleId = string` 是宽松 index signature、`LOCALE_IDS` 仍为 `["zh","en"]`，插件 `register(ns, { zh, en })` 调用完全兼容 |
| `dsh-client-ui-primitives` | 大量新组件（DetailDocument/ZoomControls/AnimatedRows 等）与 CSS 调整；`Button.d.ts` 仅注释变化；**插件用的 7 个图标基名 × Medium 变体 + `Button`/`Input`/`Pill`/`StateDot`/`Toast` 在编译产物 export 列表（310 项）中全部在**；`icons.ts` 的 Empty 兜底机制不变 |
| `dsh-client-ui-settings` | 新增 `settings.section.icon` 插槽（加法）；客户端 store 内部变化 |
| `dsh-client-ui-slots` | **逐字节未变** |
| `dsh-system-prompt` | `PromptAssembly` 拆为 `PromptPresentation`（无 tools）+ `PromptAssembly extends PromptPresentation`；`'system-prompt/assemble'` 事件签名随之变化——**插件只调 `section({name, order, text})`，不监听该事件**；order 常量新增不影响插件的 order: 50 |
| `dsh-settings` | 内部实现变化（fiber 引用方式改 `fiber.ctx.fiber`、`effectiveConfig`，与 cordis 4.1 配套）；`src/compat/settings.ts` 的两代特征检测（installSection/configure）不受影响 |
| `dsh-api-remotes` | 客户端 API 纯加法重导出（BundleDetail、PluginUpdate* 系列、PluginDetail 等） |
| `dsh-app-boot` | **`evaluatePluginCompatibility` 门禁逻辑与 0.2.1 完全一致**：`engines.dsh` 声明则单独裁决、否则查 `@deepseek-ai/dsh`/`dsh-*` peer，`semver.satisfies(runtimeVersion, range, { includePrerelease: true })`；新增 official-bundles/startup-diagnostics 类型（宿主内部） |
| cordis 4.0.5 → 4.1.0 | `Context` 公开类型面仅 `baseUrl?: string` → `string \| undefined`（等价）；fiber 内部重构（`_config`/`store` → `rawConfig`/`committed`/`provisions`），插件只 import `Context` 类型 + 公开 ctx API，不受影响 |
| schemastery 3.18.5 → 3.19.0 | `lib/` **零差异**（纯版本重发布） |

## 版本与发布事实

- npm：`@deepseek-ai/dsh` dist-tags `latest` = `next` = `0.2.2-rc.1`（2026-11-04）；
  `alpha` = `0.2.2-alpha.3`（2026-11-03）。全部 `dsh-*` 框架包同步发了 rc.1。
- 0.2.2 代宿主钉 cordis `~4.1.0`（上代 `~4.0.5`）、schemastery `~3.19.0`（上代
  `~3.18.5`，两版零差异）。

## 采纳的改动

1. peer 三项 `>=0.1.5-rc.3 <0.2.2-0` → `>=0.1.5-rc.3 <0.2.3-0`（上限收到 0.2.2 一代，
   0.2.3 出来后按惯例先跑矩阵再扩）。
2. devDependencies 的 `@deepseek-ai/dsh-*` 全部 0.2.1-rc.1 → 0.2.2-rc.1、cordis
   4.0.5 → 4.1.0、schemastery 3.18.5 → 3.19.0（类型检查基线换到最新一代，对齐宿主代）。
3. `scripts/test-compat.mjs` 矩阵加一代：0.2.1-rc.5（cordis 4.0.5 / schemastery
   3.18.5），原有三代（0.2.0-rc.2 / 0.1.7-rc.1 / 0.1.5-rc.3）保留。
