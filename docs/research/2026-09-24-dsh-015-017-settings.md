- `$S` = 调研时的临时 scratchpad 目录

- `$P5` = `$S/pack015/<pkg>/package`（本次 `npm pack` 下来的 0.1.5-rc.3 官方包）

## 结论速览

| 维度 | 0.1.1（现状） | 0.1.5-rc.3 | 0.1.7-rc.1 |
|---|---|---|---|
| 设置服务 | `SettingsProvider`，namespace 注册制 | 同上，但 **`installSettingsSection`/`settingsNamespace` 不再从包导出**，改为服务方法 `ctx.settings.installSection` | **整个换掉**：`SettingsForms`，不再有 namespace 注册，按 **profile 条目 id** 投影插件 Config 里 `.volatile()` 的字段 |
| 读合并值 + 热更 | `setSource/onChange` | 同左（`installSection` 的 hooks） | 插件直接读自己 Config 里的 `Volatile` 引用 `.get()`，监听 `loader/volatile-update`；非 volatile 字段改动 = fiber 重启（dispose+重新 apply） |
| 写 | `settings.update(ns, patch)` 写 `settings.yaml` | 同左（ns 必须已注册） | `settings.update(entryId, patch)`（只能写 volatile 字段）或 `configEditor.edit(entry, fn)`（任意字段），都写进 profile 的 `cordis.patch.yml` |
| 卡片 slot | `settings.plugin.item`（keyed，key=namespace），Host 已服务 namespace ∩ 卡片 key | 同左 | **`settings.plugin.item` 已不存在**；改为侧栏「插件」页的 `plugins.bundle.config`（key=包名）/`plugins.row.config`（key=`包名#行id`），纯客户端 slot key 匹配，不再依赖 host namespace |
| 整页 `settings.section` | 有 | 有（形状不变） | 有（形状不变） |

**头号风险**：若把 `@deepseek-ai/dsh-settings` 升到 0.1.5/0.1.7 的钉版而保留 `import { installSettingsSection, settingsNamespace }`，ESM 链接期就会抛 SyntaxError，整个插件（连 LLM 适配器）起不来——0.1.5 的导出只剩 `SettingsConflictError, SettingsProvider, default, redactSecrets`（`$T5/dsh-settings/lib/index.js:610`），0.1.7 只剩 `SettingsConflictError, SettingsForms, default, redactSecrets`（`$T7/dsh-settings/lib/index.js:544`）。**双版本方案里必须彻底去掉对 dsh-settings 的运行时 import**，只留本地结构化类型。

## 1. dsh 0.1.5-rc.3

### 1.1 `installSettingsSection(...)` 的替代

- 0.1.1：独立函数 `installSettingsSection(ctx, ns, schema, entry, hooks)`，内部自己 `ctx.inject(["settings"], ...)`（`$T1/dsh-settings/lib/index.js:618-636`），导出于 `:638`。
- 0.1.5：变成服务方法 `SettingsProvider.installSection(owner, ns, schema, entry, hooks)`（`$T5/dsh-settings/lib/index.js:327-345`），**不再自带 inject**，调用方自己包一层 `ctx.inject(['settings'], ...)`。类型签名 `$T5/dsh-settings/lib/types/index.d.ts:228`。
- `settingsNamespace()` 已删；namespace 校验内聚在服务里 `parseSettingsNamespace`，规则不变 `/^[a-z][a-z0-9-]*$/`（`:82-86`）。`llamapad-panel` 仍合法。

精确替换：

```ts
ctx.inject(["settings"], (sctx) => {
  sctx.settings.installSection(ctx, "llamapad-panel", PlainConfig, plainEntry, {
    setSource: (source) => { current = source; },
    onChange: syncConnection,
  });
});
```

`owner` 传插件自身的 `ctx`（不是 `sctx`）：它只用于判断「是插件自己在卸载」还是「只是 settings 服务走了」（`isUnloading(owner)`，`:605-608`）。

### 1.2 `settings.update(settingsNamespace(ns), patch)` 的替代

`sctx.settings.update("llamapad-panel", patch)`（`:403-405`），语义不变：深合并进用户分节、schema 校验、经 provider 持久化（`settings.yaml`）。namespace 未注册会拒绝（`:446` "is not registered"）。建议改用 `ctx.get("settings")` 现取服务，而不是每次 `ctx.inject(...)` 包 Promise——现行 `writeSettings`（`src/index.ts:322-327`）每次保存都会新建一个常驻的 inject 子 fiber，属于小泄漏。

### 1.3 provider 挂载/卸载如何处理（服务缺席时是否可用）

`installSection` 源码（`$T5/dsh-settings/lib/index.js:327-345`）：

1. `this.register(ns, schema, {base: entry})`：注册在 `this.ctx` fiber 上的 effect（`:294-297`）。cordis 服务代理把 `this.ctx` 追踪成**调用方上下文**（`$T5/cordis/lib/index.js:123-128`，`if (prop === tracker.property) return ctx`），也就是 `ctx.inject` 的子上下文 `sctx`。
2. `hooks.setSource(() => scope.get())` 后立即同步调一次 `hooks.onChange()`（`:332`、`:339`）。
3. `this.ctx.effect(() => () => { if (isUnloading(owner)) return; hooks.setSource(() => entry); hooks.onChange(); })`（`:333-338`）：settings 服务消失时 inject 子 fiber 被 dispose，source 退回组合配置 `entry` 并通知一次；插件自身卸载则什么都不做。
4. `scope.watch(...)` → 每次提交调 `onChange`（`:340-343`）。

服务从未挂载时 `ctx.inject` 的回调根本不跑，`current` 保持初值 `() => config`，与 0.1.1 行为一致。**服务缺席时照常可用。**

### 1.4 `ctx.inject(['settings'], ...)` 仍是正确姿势——官方 0.1.5 插件示范

- `@deepseek-ai/dsh-web-search-deepseek@0.1.5-rc.3`（`$P5/deepseek-ai-dsh-web-search-deepseek-0.1.5-rc.3/package/lib/index.js:293-303`）：

  ```js
  function apply(ctx, config) {
    let current = () => config;
    ctx.inject(["settings"], (settingsCtx) => {
      settingsCtx.settings.installSection(ctx, WEB_SEARCH_DEEPSEEK_SETTINGS_NAMESPACE, Config, config, {
        setSource: (source) => { current = source; },
        onChange: () => {}
      });
    });
    ctx.web.registerSearchProvider(new DeepSeekSearchProvider(() => resolveOptions(ctx, current())));
  }
  ```

  namespace 是 `"web-search-deepseek"`（`:261`）。
- 同样写法：`dsh-bash-local`（`.../lib/index.js:147-148`）、`dsh-agent-loop`（`.../lib/index.js:1519-1520`）。

### 1.5 0.1.5 的陷阱：Config 若带 volatile 不能直接交给 `installSection`

（仅在第 5 节方案给 Config 加 `.volatile()` 时相关。）`register()` 立刻用 schema 解析 `base`（`:290`）；schemastery 3.18.4 遇到 volatile 节点会把输入按内层类型解析（`$H/schemastery/src/index.ts:519-528`），而插件 `apply` 收到的 `config` 里对应字段已经是 `Volatile` 对象 → 解析报 "expected string"，注册直接抛错，卡片就没了。即便绕过去，`describe()` 里的 `structuredClone(registration.base)`（`:359`）遇到带函数的 Volatile 对象也会抛 DataCloneError，把**所有插件**的 describe 一起拖垮。所以 0.1.5 分支必须传「不带 volatile 的 PlainConfig」和「解包后的 plainEntry」。

## 2. dsh 0.1.7-rc.1

### 2.1 SettingsForms 与插件 Config 的关系

`$T7/dsh-settings/README.zh.md`：「编辑插件通过 `.volatile()` 声明的字段……表单以 profile 条目 id 标识插件……更改通过当前 profile 的 Cordis patch 持久化。」

- 服务类 `SettingsForms extends Service`，`static inject = ["configEditor","profileContext"]`（`$T7/dsh-settings/lib/index.js:324`），挂载名仍是 `"settings"`（`:330`）。**已经没有 `register`/`installSection`/`get`/`watch` 这些方法**，namespace 注册制整体删除。
- `describe()`（`:413-466`）遍历 `configEditor.configuration()` 的每个 profile 条目，取 `entry.fiber.runtime.Config`，经 `volatileForm(schema)`（`:122-132`）只挑出 `meta.volatile` 的字段；一个 volatile 字段都没有的插件不出现（`:419`）；fiber 不是 active（`state !== 2`）的也不出现（`:417`）。descriptor 的 `ns` 就是 `entry.options.id`（`:432`、`:443`）。
- 业务插件不再从 settings 服务读值：「业务插件直接读取自己的 Config 引用」（README「理解实现」）。

### 2.2 用户改了配置，运行中的插件怎么看到新值

写路径：`settings.update(ns, patch)`（`:470-473`）→ `write()`（`:501-534`）→ `configEditor.edit(entry, fn)`（`$H/dsh-config-editor/lib/index.js:63-129`）→ 写 profile patch 后 `reconcileProfilePatches(root, patches, "dsh", [entry.id])`（`:119`）→ Loader `Entry.update`（`$H/cordis-plugin-loader/lib/index.js:366-389`）。

- **只改了 volatile 字段**（`equalExceptVolatile`，`:380`）→ `_commitVolatile()`（`:393-424`）：用插件 Config 重新解析候选值，把新值写进**运行中那份 config 里的同一批 `Volatile` 引用**（`updateVolatile`，`:411-414`），然后只向该插件 fiber 发 `loader/volatile-update(paths)`（`:417-420`，`self[Context.filter] = owner => owner.fiber === fiber`）。**不重启 fiber**。候选值非法只记日志，引用不变（`:400-404`）。
- **改到了普通字段**（或 volatile 与普通字段一起变）→ `_commitVolatile` 返回 false（`:406-409`）→ `_patchContext` → `fiber.update(config, true)` → cordis `Fiber.update`（`$H/cordis/lib/index.js:1427-1443`）→ `internal/update` 瀑布末端 `this.restart()`，也就是 **dispose 旧 fiber + 用新 config 重新 apply**。（插件可以挂非 global 的 `internal/update` 钩子拦截重启，`:237-249`，但这是 internal 事件，不建议依赖。）

所以「live」的判定只有一条：**schema 节点带 `meta.volatile`**，由 schemastery 3.18.4 的 `Schema.prototype.volatile()` 设置（`$H/schemastery/src/index.ts:480-483`）；只允许放在固定对象路径上，不能嵌在另一个 volatile 或数组/字典里（`:486-510`）。解析产物是 `Volatile<T>`（`$H/cosmokit/src/volatile.ts:9-12`，`.get()` 返回冻结快照；跨模块副本靠 `Symbol.for('cosmokit.volatile.write')` 识别，`:3`、`:52-54`）。

官方 0.1.7 LLM 适配器的写法可以直接照抄（`$H/dsh-llm-deepseek/lib/index.js`）：

- `:2014-2016` `plainOptions(config)`：逐字段 `isVolatile(v) ? v.get() : v` 解包，每次用时现取；
- `:2173-2175` `ctx.inject(["settings"], child => child.effect(() => child.settings.configure({ auto: false }, ctx.fiber)))`；
- `:2228` `ctx.on("loader/volatile-update", ensureRegistrationFacts)` 挂在**插件自身 ctx** 上。

注意：`loader/volatile-update` 只投递给 `owner.fiber === 插件 fiber` 的监听器，挂在 `ctx.inject(...)` 子上下文里的监听器（子 fiber）**收不到**。

### 2.3 `configure({auto})` / autoGenerate；会不会给我们自动生成表单、与自定义卡片重复

- `configure(presentation, owner = this.ctx.fiber)`（`$T7/dsh-settings/lib/index.js:364-383`）：登记某个插件实例的页面策略，返回 disposer；每个 descriptor 带 `autoGenerate = presentations.get(fiber)?.auto ?? true`（`:426`）。
- README：「每个表单报告 `autoGenerate`（默认开启），供按 schema 生成页面的客户端使用；**目前没有已发布的客户端这样做**。自带页面的插件在 `apply` 中于可选的 `ctx.inject(['settings'], ...)` 子级内以 effect 注册 `configure({ auto: false }, ctx.fiber)`。」
- 在线上宿主里 grep 过：`autoGenerate` 只出现在 dsh-settings、dsh-api-settings-controller、dsh-api-remotes 的透传代码里，没有任何 UI 包消费它。`configure({auto:false})` 的调用者有 dsh-llm-deepseek、dsh-agent-default-model、dsh-client-ui-settings、dsh-permission-presets 等 10 个包。
- 结论：**0.1.7 目前不会给我们自动生成表单，也就不会和卡片重复**。插件管理页只有在某个 `plugins.row.config` 条目点名某一行时才会出现行页（`$H/dsh-client-ui-plugin-manager/README.zh.md`「行页只在某个 `plugins.row.config` 条目点名这一行时存在」）。为了前向兼容仍建议调用 `configure({auto:false})`（用 `typeof settings.configure === "function"` 做特征检测）。

### 2.4 我们这一行的 profile 条目 id

`llamapad`。bundle 层 `cordis.patch.yml` 写的是 `insert: [{ id: llamapad, name: llamapad-dsh-plugin }]`，用户层 `~/.dsh/profiles/web/cordis.patch.yml` 用同 id 覆盖。`configEditor.entries()` 只收**根 include 下 id 唯一**的条目（`$H/dsh-config-editor/lib/index.js:30-35`）。bundle 注入的行在根 include 下：旁证是用户层同一份 patch 里的 `agent-default-model`、`ui-settings-general` 这两个 bundle 行都已被 settings.yaml 的遗留导入写进了配置（见第 3 节）。建议运行时用 `ctx.fiber.entry.options.id` 取 id，不要写死（loader 在 `$H/cordis-plugin-loader/lib/index.js:626-627` 设置 `fiber.entry`）。

### 2.5 插件能否写自己条目的配置（给卡片的 saveConnection 用）

两条路都可以：

**A. `settings.update(entryId, patch)`**（`$T7/dsh-settings/lib/index.js:470-473`、`:501-534`）
- 前提：条目在 `configEditor.entries()` 里（`:503-504`，否则抛 `No configurable plugin entry`）；Config 至少有一个 volatile 字段（`:506`，否则抛 `has no volatile fields`）；patch 里每个字段都在 volatile 路径下（`:512-521`，否则抛 `Config field "x" is not volatile`）。所以 **`panelUrl`、`token` 必须 `.volatile()`**。
- 写入内容：`mergeLayers(strip(raw, form), next)`（`:522-532`），`raw` 取自 `entry.options.config`（`$H/dsh-config-editor/lib/index.js:71`），即组合后的完整原始 config，因此会把下层（bundle 层）的普通字段也固定进 profile 层（config-editor README 已知限制第 2 条）。本插件的 bundle 层不带 config，这点影响很小。

**B. `configEditor.edit(entry, (current, inherited) => nextFullConfig)`**（`$H/dsh-config-editor/lib/index.js:63-129`），官方 `dsh-agent-default-model` 就是这么写的（`$H/dsh-agent-default-model/lib/index.js:51-59`）：

```js
const entry = this.ownerContext.fiber.entry;
if (entry === void 0) return;
await this.ctx.get("configEditor")?.edit(entry, () => ({ provider, model, ... }));
```

- 回调返回的是**整份** config（`:104` `setIn([index,"config"], next)` 整体替换），我们要写成 `current => ({ ...current, ...patch })`。
- 任意字段都能写；但普通字段一变就会走重启路径（2.2）。

**用户层 patch 是否必须存在？不需要**：文件不存在按 `"[]"` 处理（`:81-84`）；找不到 `id` 匹配、非 `insert`、`name` 相同或缺省的行时，会新增 `{id, name, config}` 一行（`:92`、`:99-103`）。写入会被拒绝的情况有两种：home patch 或命令行 `--patch` overlay 覆盖了同一 config（`:116`，报 `overridden by a home patch or command-line overlay`）；条目在写入期间被替换或不再 active（`:67`、`:70`、`:75`）。写入前会用插件 Config 校验完整候选值（`:76-77`），文件以 0600 原子写（`:117`），reconcile 失败会回滚（`:120-123`）。

**时序**（对 saveConnection 很关键）：`edit()` 在 `reconcileProfilePatches` 完成后才 resolve；volatile 提交与 `loader/volatile-update` 是在 `Entry.update` 里同步发出的（`$H/cordis-plugin-loader/lib/index.js:382`、`:417-420`），所以 `await write(...)` 返回时 `syncConnection` 已经跑过，紧接着 `buildSnapshot()` 能看到新 client。**如果 panelUrl/token 不是 volatile**，`edit()` 会在 RPC 调用过程中把插件 fiber 重启掉：gateway 实例被 dispose，事件环/fleetCache 清空，这次 RPC 回包能否送达**未验证**。

### 2.6 secret（token）怎么处理

- `role('secret')` 仍然有效。`plainSchema()`（`$T7/dsh-settings/lib/index.js:103-117`）会去掉 secret 字段的 `default`/`required`；`describe({redactSecrets:true})` 从 value/base/user 三层剥离 secret，改为返回 `{path,set}` 存在性标记（`:440-452`）。`mutate` 做路径编辑时不需要回传秘密值（`:486-500`）。
- 存储：明文写进 profile 的 `cordis.patch.yml`，文件权限 0600。现状是明文写 `~/.dsh/settings.yaml`，两者等价。若用户原来用 `!!js process.env.X` 注入 token，卡片保存新 token 后该表达式会被字面值覆盖，未改动的 `!!js` 节点会保留（`$H/dsh-config-editor/lib/index.js:85-88`、`:105-110`）。
- 我们的卡片走自有 RPC，token 从不下发到浏览器，这一点与版本无关。

## 3. 0.1.7 遗留导入 `importLegacyDocument`

`$T7/dsh-settings/lib/index.js:346-362`：

- 触发：settings 服务构造时 `ctx.root.loader.await().then(() => this.importLegacyDocument())`（`:338-340`），只在 `<profile.home>/settings.yaml` 存在时执行一次，**先改名**为 `settings.yaml.imported` 再写（`:349-351`）。
- key 映射：`const ns = LEGACY_SECTION_ENTRIES[section] ?? section`（`:354`），表里只有 3 条硬编码：`ui-developer-tools → ui-settings`、`ui-onboarding → ui-settings-general`、`shell → bash-sandbox/pwsh-sandbox`（`:303-308`），**其余一律原名当作条目 id**，然后调 `this.update(ns, values)`。
- 我们的 `llamapad-panel` 会被当成条目 id `llamapad-panel` → `write()` 找不到该条目，抛 `No configurable plugin entry "llamapad-panel"`（`:504`）→ 捕获后打 warn `section %s of %s was not imported into entry %s`（`:357-359`）→ **被丢弃**，只留在 `settings.yaml.imported` 里。就算节名恰好是 `llamapad`，也要求导入那一刻 Config 有 volatile 的 panelUrl/token 且 fiber 处于 active，否则同样被拒（`:506`、`:512-521`）。
- 本机实况：`~/.dsh/settings.yaml.imported`（2026-09-21）里有 `ui-onboarding`、`agent-default-model`、`llamapad-panel` 三节；用户层 patch 里出现了 `ui-settings-general.welcomeNoticeVersion`（来自 `ui-onboarding` 的映射）与 `agent-default-model`，与上面的代码吻合。导入已经跑过，不会再跑。`llamapad` 行里的 panelUrl/token 与 `llamapad-panel` 节取值相同，但无法区分是用户手写还是其他途径写入的；按代码判断**不是**导入写的。

## 4. 客户端 slot：`settings.plugin.item` / `settings.section`

### 4.1 0.1.5-rc.3（与 0.1.1 一致）

- `settings.section`：由 ui-settings 的 slot 契约声明，`kind:'list'`、`scope:'root'`，owner props `{ close }`（`$T5/dsh-client-ui-settings/lib/types/client/contract/slots.d.ts:67-71`、`:148-151`；与 0.1.1 版逐字节相同，已 diff）。注册形状 `{ name, id, order, label, locale, inject }`，官方示例 `$P5/deepseek-ai-dsh-client-ui-settings-plugins-0.1.5-rc.3/package/lib/client.js:1774-1784`（`id:"plugins", order:15, label:()=>t("nav")`）。
- `settings.plugin.item`：由 dsh-client-ui-settings-plugins 在「configurable」标签页上**运行期声明**为子 slot，`kind:'keyed'`（`.../lib/client.js:1785-1797`；类型 `.../lib/types/client/slot-contract.d.ts:16-30`）。注册形状 `{ name:"settings.plugin.item", key:<namespace>, locale, inject }`（官方卡片 `:1798-1822`）。

### 4.2 0.1.7-rc.1

## 5. 双版本设计方案

### 5.0 前置：依赖与 Config

1. **去掉 `@deepseek-ai/dsh-settings` 的运行时 import**（1.1 与开头的风险说明）。在 `src/compat/settings.ts` 本地声明两个结构化接口：`SettingsV015Like { installSection; update }` 和 `SettingsV017Like { configure; update; describe }`，外加 `ConfigEditorLike { edit }`。
2. schemastery 钉到 **3.18.4**：npm 上已有，0.1.7 的 peer 是 `~3.18.4`。0.1.5 宿主用的是 3.18.2（`npm view @deepseek-ai/dsh@0.1.5-rc.3 dependencies`），3.18.2 没有 `volatile`（grep 为 0 处）。Config 的解析由**我们自己那份** schemastery 完成（运行时依赖是 external，但 pnpm 按本包钉版落盘），所以 volatile 与否由本包决定。另外做一层防御：`const live = (s) => typeof s.volatile === "function" ? s.volatile() : s`，万一解析到的副本没有该方法就退化为普通字段。
3. 同一份字段表生成两个 schema：
   - `Config`（导出给 cordis）：可热更的字段套 `live()`。建议 volatile 的：`panelUrl, token, panelPublicUrl, mode, llamaBaseUrl, chatBehavior, startTimeoutMs, pollIntervalMs, drainOnSwitch, drainTimeoutMs, requestTimeoutMs, defaultContextWindow, hideStoppedModels, statusPromptSection`。**不** volatile 的：`provider`（`registerAdapter` 的键）、`statusRefreshMs`（watcher 启动参数）。这两个改动走 fiber 重启，与现在「需重载」的语义一致。
   - `PlainConfig`：同一张表、不套 volatile，只给 0.1.5 的 `installSection` 用（1.5）。
4. 统一解包：`plain(config) = Object.fromEntries(Object.entries(config).map(([k,v]) => [k, isVolatile(v) ? v.get() : v]))`，照 dsh-llm-deepseek 的 `plainOptions`。`isVolatile` 可以用 `Symbol.for('cosmokit.volatile.write') in v` 自己实现，不必多依赖 cosmokit。`assertStaticConfig` 等所有读 config 的地方都改为读 `plain(config)`。0.1.5 宿主上 Config 同样会产出 Volatile 引用（解析用的是我们的 3.18.4），所以两个版本都要解包。
5. B 形态 `tools.ts` 的 Config 不涉及 settings，保持原样即可（0.1.7 下改它会重启该 fiber，属可接受）。

### 5.1 `src/compat/settings.ts` 接口草案

```ts
export interface SettingsBinding {
  /** 当前生效配置（已解包）。 */
  current(): Config;
  /** 给 saveConnection 用的写口。 */
  write(patch: Partial<Config>): Promise<void>;
}
export function bindSettings(ctx, config, { onChange }): SettingsBinding
```

内部逻辑：

```ts
let current = () => plain(config);
// (a) 0.1.7 的热更路径不依赖 settings 服务，无条件挂在插件自身 ctx 上（0.1.5 上该事件永不触发，无副作用）
ctx.on("loader/volatile-update", () => onChange());

ctx.inject(["settings"], (sctx) => {
  const s = sctx.settings as any;
  if (typeof s.installSection === "function") {           // 0.1.5
    s.installSection(ctx, SETTINGS_NAMESPACE, PlainConfig, plain(config), {
      setSource: (src) => { current = () => src(); },
      onChange,
    });
  } else if (typeof s.configure === "function") {          // 0.1.7
    sctx.effect(() => s.configure({ auto: false }, ctx.fiber));
  } else if (typeof s.register === "function") {           // 可选：0.1.1 兜底，照 $T1:618-636 手写
    /* register + watch + effect */
  }
});
```

### 5.2 各分支的具体行为

**(a) 读合并值与热更**

- 0.1.5：`installSection` 挂载时同步 `setSource(scope.get)` 并调一次 `onChange`；之后 settings.yaml 的每次提交走 `watch → onChange`；服务消失时回落到 `plain(config)` 并调一次 `onChange`。`current()` 返回「schema 默认 < cordis.yml < settings.yaml」的合并值，**所有字段都可热更**，与现状一致。cordis.yml 本身改动时，loader 1.0.3 没有 volatile 支持（该包 grep `volatile` 为 0 处），走 fiber 重启，也与现状一致。
- 0.1.7：`current()` 每次现取 `plain(config)`，读到的就是被 `_commitVolatile` 就地更新过的引用；`loader/volatile-update` 触发 `onChange → syncConnection`。非 volatile 字段改动 → fiber 重启 → 重新 apply（事件环与 fleetCache 会丢，CLAUDE.md 里「别当可随手重建的缓存」那条约束在这条路径上无法保证，只能靠把高频字段都设为 volatile 来规避）。`syncConnection` 依旧改写 `adapterOptions/gatewayOptions`，CLAUDE.md「options 原地改写」的约束**完整保留**。
- 建议顺带把 `statusPromptSection` 改为「总是注册 section、false 时渲染空串」，这样 0.1.7 下 false→true 也能热生效（现状只支持 true→false）。

**(b) saveConnection 写入**（`PanelGateway` 构造参数里的 `writeSettings` 改为 `binding.write`）

- 0.1.5：`ctx.get("settings")?.update("llamapad-panel", patch)`；服务缺席时抛出可读错误（卡片此时本来也渲染不出来）。
- 0.1.7：优先 `ctx.get("settings")?.update(ctx.fiber.entry.options.id, patch)`（前提是 panelUrl/token 已 volatile，写入只动 volatile 字段、不会误触重启，写后 `describe()` 会刷新 revision 并发 `settings/document-updated`）；settings 服务缺席时退到 `ctx.get("configEditor")?.edit(ctx.fiber.entry, cur => ({ ...cur, ...patch }))`（官方 agent-default-model 模式）；两者都缺席时抛错。
- 分支判别用同一套特征检测：`typeof s.installSection === "function"` → 0.1.5，`typeof s.configure === "function"` → 0.1.7。`ctx.get(...)` 在未声明 inject 时也允许调用（本仓库 `readImageFromAttachmentStore` 已这样用 `ctx.get("attachments")`）。
- 0.1.7 下写入失败的新错误形态（被 home patch/overlay 覆盖、条目不可用）会走现有的 `panelError` 横幅，文案需要补齐。

**(c) 卡片可见性**

- host 侧：0.1.5 必须 `installSection("llamapad-panel", …)`，否则交集为空、卡片不派发，这正是现有代码「缺配置也无条件注册」那条约束；0.1.7 host 侧无需任何动作。
- client 侧（`src/client/index.tsx`）**三处都注册**：`slots.inject` 对未声明的 slot 只是挂起等待，不会报错。
  1. `settings.plugin.item`，`key: "llamapad-panel"`（0.1.5 生效，0.1.7 永远挂起）；
  2. `plugins.bundle.config`，`key: "llamapad-dsh-plugin"`（0.1.7 生效，推荐主入口：卡片管理的是整个 bundle 的连接，A/B 两行共用）；
  3. 可选 `plugins.row.config`，`key: "llamapad-dsh-plugin#llamapad"`（提供独立页面加 `summary` 一句话）。
  4. `settings.section` 监控页原样保留。
- `Card` 组件要能兼容两种 owner props：0.1.5 为 `{}`，0.1.7 为 `{view, form?}`。`view === "summary"` 时只返回一句话；我们不消费 `form`。
- 包名 key 不要写死字符串，从 `package.json` 的 `name` 取（构建期注入）。

### 5.3 做不到或行为有变的地方，及建议兜底

1. **0.1.7 没有独立的 settings 层**：保存会直接改写 profile `cordis.patch.yml` 里用户手写的 `llamapad.config`，不再是「settings.yaml 覆盖 cordis.yml」的两层关系；注释会保留，被改写的节点替换为字面值。home patch 或 `--patch` overlay 固定了 panelUrl 时，保存会被拒。→ 卡片文案去掉 settings.yaml 字样，错误映射成可读提示。
2. **0.1.7 非 volatile 字段不能热更**（`provider`、`statusRefreshMs`）→ 必然重启 fiber，事件环历史丢失。→ 文档注明；需要热更的字段一律 volatile。
3. **遗留 `llamapad-panel` 节在 0.1.7 首次启动时被丢弃**（第 3 节）。→ 可选的自迁移：0.1.7 分支 apply 时，若 `<profileContext.home>/settings.yaml.imported`（或尚未改名的 `settings.yaml`）里有 `llamapad-panel` 节、且当前 config 没配 panelUrl，就经 `configEditor.edit` 写回一次，否则至少打一条 warn 提示用户手动迁移。本机导入已经跑过，数据还在 `.imported` 里。
4. **0.1.5 不能把 volatile Config 和原始 entry 交给 `installSection`**（1.5）→ 必须用 PlainConfig + `plain(config)`，这是双 schema 的根本原因。
5. **类型**：`Schema<Partial<Config>, Config>` 的手写声明对 volatile 字段的输出类型（`Volatile<T>`）不再准确 → `apply(ctx, raw: unknown)` 入口统一走 `plain()`，内部只用解包后的 `Config`。
6. 测试：`test/unit/index.test.ts` 的 fake settings 现在只桩了 `register`（`:37-45`），需要拆成三种 fake：0.1.5（`installSection`）、0.1.7（`configure`，再加一个模拟 `loader/volatile-update` 的 `ctx.emit`）、以及无服务。
