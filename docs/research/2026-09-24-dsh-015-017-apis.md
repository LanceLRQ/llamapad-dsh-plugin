# llamapad-dsh-plugin 双版本兼容（0.1.5-rc.3 / 0.1.7-rc.1）API 研究

归档说明：下文表格与正文里出现的具体文件路径，均指调研当时（2026-09-24）在两份临时全量安装
副本（0.1.5-rc.3 / 0.1.7-rc.1）里核对时的位置，仓库里并不存在，仅作溯源之用，不代表当前
可复现路径。

调研方法：在两份全量安装的副本里跑 `npx tsc --noEmit`，逐条错误定位到框架 `.d.ts` 的
具体行；再对两份 `node_modules/@deepseek-ai/*` 的 `lib/types/*.d.ts` 做 `diff -u`，
逐个补全 TS 编译不报错但运行期契约已变的地方；`dsh-web-frontend` 用 `npm pack` 下载
两个版本核对浏览器端模块种子表。settings（`dsh-settings`）按要求跳过。

## 3. 关键结论汇总

1. **确定要改的代码（阻塞编译/运行）**
   - `src/translate.ts`、`test/unit/openai-wire.test.ts`：`CallId` → `ToolCallId`（两版本一致，纯改名，无需双兼容分支）。
   - `src/openai-wire.ts`：`collectImages`/`mapMessage` 需要同时认得"`tool-result` 内容块挂在 `user` 消息里"（0.1.5）与"`role:'tool'` 独立消息 + 顶层 `toolCallId`"（0.1.7）两种形状，按 `message.role === 'tool'` 做运行时分支。
   - `src/rpc-contract.ts`：`strict()`/`StrictCodec<T>` 需要同时产出 `schema.parse`（0.1.5 宿主读）与 `create().parse`（0.1.7 宿主读）两套字段。
   - `src/index.ts:252`：`invocations: RPC_CONTRIBUTION.descriptors` 的类型报错会随上一条 `StrictCodec` 改法自然消失（本身类型契约无新增差异，只是 codec 形状对不上）。
   - `src/client/Card.tsx`、`src/client/MonitorPage.tsx`：7 个图标改名，且**没有能同时满足两个版本的静态具名 import**——必须改成 `import * as Icons` + 运行时按存在性取用（`Icons.IconXxxMedium ?? Icons.IconXxx16`），同时给每处调用显式传 `size`，因为旧名字的默认像素大小语义在新组件上不再成立。

2. **确认安全、无需改动的面（已逐一核对两版本 `.d.ts` 逐字节 diff）**
   - `LlmAdapter` 抽象类全部方法签名（`providerInfo`/`listModels`/`resolveModel`/`stream`/`imageRequestPricing`/`providerRetryPolicy`）。
   - `LlmResolvedModelInfo`/`LlmModelInfo`/`inputModalities`/`reasoning`/`context` 等 adapter 返回值形状。
   - `ctx.llm.registerAdapter`、`llm/adapters-updated` 事件签名。
   - `dsh-attachment` 的 `AttachmentStore.readImage(ref, signal?)`（插件唯一用到的方法；`readImageRequest` 改了参数但插件未触达）。
   - `dsh-tools` 的 `defineTool`/`ToolDefinition`/`isConcurrencySafe`/`execute`/`presentation.d.ts`（presentation.d.ts 两版本逐字节相同）。
   - `dsh-system-prompt` 的 `section()` 调用形状（新增字段全部可选）。
   - `dsh-typert-protocol` 的 `TypertRemoteService`/`@Remote`/`RemoteMethodOptions`（插件用到的部分）。
   - `dsh-client-ui-slots` 的 `register`/`inject` 运行时函数签名（插件走 `any`，类型层新增内容不影响）。
   - `dsh-web-frontend` 浏览器端模块种子表七项 external。

3. **未验证 / 需要人工复核的点（本报告已标注，不代表已解决）**
   - `settings.plugin.item` 这个 slot key 与 `dsh-client-ui-settings` README 提到的 `settings.plugins.tab` 是否为同一概念的不同措辞、还是两代 API 的又一处改名——按任务要求跳过 settings 专项，留给该调研确认。
   - 图标改名的"14/16 全部映射到 Medium"是基于 `tsc` 的 "Did you mean" 字符串近似匹配 + `icons/index.d.ts` 里 Regular=1px/Medium=1.3px 描边粗细的语义描述做出的**最佳猜测**，不是逐图标视觉核对；建议改完后过一遍浏览器截图确认粗细/大小观感与旧版一致。
   - `@deepseek-ai/dsh-client-runtime` 这个 devDependency 在两个 try 副本里都没有对应的 `node_modules` 目录，怀疑是 pnpm 装不出来后被忽略/降级，建议检查两份 try 副本各自的 `pnpm install` 日志或 `pnpm-lock.yaml` 确认是否真的静默失败，而不是本报告的 `ls node_modules/@deepseek-ai/` 检查覆盖不到某个 hoist 路径。
   - 本报告未对 `dsh-api-gateway`（SRC 反射/`resolveSrcDescriptor`）、`dsh-client-ui-settings` 之外的浏览器专属类型基础设施（`SlotFactoryMap` 全套泛型）做逐行 diff，因为插件代码未触达；如果后续要用这些新能力再单独核对。
